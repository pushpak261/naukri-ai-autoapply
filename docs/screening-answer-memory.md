Both agents and the external employer-form engine share the account's local
answer memory. Confirmed answers take priority over profile-derived drafts.
Changing an answer replaces its older variants; forgetting it invalidates older
native answer caches.

Equivalent questions such as “Are you willing to relocate?” and “Are you open to
relocation?” reuse one confirmation. Matching uses complete, controlled question
patterns. Different cities, technologies, experience units, versions, thresholds
and negations remain separate. Existing memory IDs and confirmations survive
the schema upgrade.

The bot can write introductions, motivation, role-fit and project answers from
saved experience, supported skills, resume projects and the advertised job. It
selects relevant evidence, respects text-length limits and retains structured
project details when converting the resume for LinkedIn. These answers work
without Gemini. Profile changes refresh drafts; changes to the job refresh its
job-specific drafts. A confirmed answer is not replaced by generated prose.

Form readers keep question labels separate from option and textarea content.
LinkedIn radio controls support accessible labels and explicit boolean values.
External job-save widgets do not become application questions. Older malformed
radio prompts are retired when a corrected question is observed, preserving the
original records while allowing confirmed applications to resume.

Unknown qualifications, availability, declarations and personal facts appear in
Screening answers for confirmation, including optional native screening fields.
They are never changed to a positive answer
simply to complete a form. Confirmed answers are reused on compatible future
forms. The bot checks form validity and a submission receipt before counting an
application. Memory improves retrieval and drafting; it does not fine-tune the
underlying Gemini model.
